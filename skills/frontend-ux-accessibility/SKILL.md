# Frontend UX and Accessibility Skill

## Purpose
Build polished, accessible, responsive interfaces that feel production-ready.

## Workflow
1. Identify framework, routing model, styling system, component library, state management, and design tokens.
2. Preserve existing visual language unless the user asks for redesign.
3. Ensure semantic HTML, keyboard navigation, focus states, labels, alt text, contrast, and reduced-motion handling.
4. Avoid generic AI-looking UI: choose a clear visual direction, spacing system, hierarchy, and empty/loading/error states.
5. Verify responsive states for mobile, tablet, desktop.
6. Watch for hydration errors, unstable keys, unnecessary client components, large bundles, and expensive re-renders.

## Checks
- Main interactions usable by keyboard.
- Forms have labels and validation messages.
- Loading, empty, error, and success states exist.
- No layout shift from missing dimensions.
- Images optimized where framework supports it.
- No inaccessible icon-only buttons.

## Output
- UX changes
- Accessibility checks
- Responsive checks
- Performance risks
- Screenshots/manual verification notes when possible
