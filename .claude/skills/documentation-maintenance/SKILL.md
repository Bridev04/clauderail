# Documentation Maintenance Skill

## Purpose
Keep documentation accurate, useful, and synced with code.

## Workflow
1. Identify the target audience: user, developer, maintainer, operator, reviewer, or recruiter.
2. Verify facts from code/config, not assumptions.
3. Prefer concise task-oriented docs with commands that actually exist.
4. Include prerequisites, env vars, setup, run, test, build, deploy, troubleshoot, and known limitations when relevant.
5. Update docs in the same patch as behavior changes.
6. For portfolio projects, explain architecture choices, tradeoffs, and how to run locally.

## Output style
- Clear headings
- Copy-paste commands
- Expected outputs where helpful
- Troubleshooting section for common failures
- No stale promises or unsupported features

## Output
- Docs updated
- Facts verified
- Remaining documentation gaps
